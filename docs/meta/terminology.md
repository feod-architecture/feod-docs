# Терминология FEOD

Этот документ фиксирует обязательные термины для пользовательской документации FEOD. Его задача - убрать расхождения между страницами, примерами и будущим глоссарием.

## Статус документа

- Документ нормативный.
- Решения из этого списка обязательны для всех авторов страниц.
- Если формулировка на странице расходится с этим документом, корректируется страница.

## Стабильные имена верхних уровней

В пользовательской документации FEOD используются только следующие имена верхних уровней:

```text
app
pages
modules
common
global
```

Правила:

- Имена пишутся только в таком виде.
- `global` - каноническое имя верхнего уровня.
- В пользовательской документации не используется форма `globals`.
- Если требуется упомянуть прошлую или альтернативную форму, это делается только как примечание о несовпадающем названии, а не как равноправный вариант.

## Русские термины

### Уровень

Основной русский термин для `app`, `pages`, `modules`, `common`, `global` - `уровень`.

Использование:

- писать: `уровень modules`, `верхний уровень pages`, `уровни FEOD`;
- не писать: `слой modules` как основной термин.

### Слой

Термин `слой` допустим только как пояснение для аудитории, знакомой с FSD.

Правила:

- `слой` не используется как основной термин в заголовках, определениях и reference-разделах;
- допустимы формулировки вида: `в FEOD это называется уровнем; для аудитории FSD это ближайший аналог слоя`;
- на одной странице нельзя свободно переключаться между `уровень` и `слой` как между полными синонимами.

## Public API

Допустимы две формы:

- `public API`
- `публичный API`

Правила употребления:

- в пределах одной страницы выбирается одна основная форма и используется последовательно;
- смысл термина не меняется при переключении языка;
- формы `публичное API`, `паблик API` и другие разговорные варианты не используются;
- если в странице есть кодовые идентификаторы, примеры импортов и ссылки на `index.ts`, предпочтительна форма `public API`;
- если страница целиком объяснительная и русскоязычная, допустима форма `публичный API`.

Нормативное значение:

> `public API` модуля - это его явный публичный контракт, через который модуль разрешено использовать извне.

## FEOD-сущность

Термин `сущность` в FEOD имеет собственный смысл и не равен термину `entity` из DDD.

Нормативное определение:

> FEOD-сущность - это файл или директория с понятной ролью в структуре проекта.

Обязательные пояснения для авторов:

- FEOD-сущность определяется своей ролью и ограничениями в структуре;
- FEOD-сущность не описывает доменную модель сама по себе;
- FEOD-сущность не должна объясняться как вариант DDD entity;
- если на странице упоминается DDD, нужно явно развести эти понятия, а не полагаться на догадку читателя.

Допустимая краткая формулировка:

> Сущность FEOD - это структурная единица с ролью, а не domain entity из DDD.

## Термины, которые нельзя смешивать

На страницах нельзя использовать в разных смыслах следующие пары:

- `уровень` и `слой`;
- `public API` и любой другой контракт модуля;
- `сущность FEOD` и `entity` из DDD;
- `global` и `globals`.

Если странице нужно ввести различие, оно проговаривается явно в одном месте и дальше поддерживается без колебаний.

## Правила для авторов

Перед публикацией страницы автор проверяет:

1. Все верхние уровни названы как `app`, `pages`, `modules`, `common`, `global`.
2. Основной термин для structure-разделов и reference-разделов - `уровень`.
3. `Слой` используется только как пояснение для читателя из FSD.
4. На странице последовательно выбрана форма `public API` или `публичный API`.
5. FEOD-сущность нигде не описана как DDD entity.
6. `global` нигде не заменён на `globals` в пользовательской документации.
