# Информационная архитектура FEOD Docs

Этот документ фиксирует нормативную информационную архитектуру пользовательской документации FEOD. Он нужен, чтобы авторы страниц, редакторы и будущая реализация сайта опирались на одну и ту же структуру.

## Статус документа

- Документ нормативный.
- Он описывает структуру контента, а не техническую реализацию сайта.
- Если локальная навигация или сайдбар расходятся с этим документом, корректируется навигация.

## Верхняя навигация

Утверждённый состав верхней навигации:

```text
Docs
Examples
Tools
Blog
Community
```

Правила:

- Пункты верхней навигации пишутся только в этом составе и порядке, пока не принято отдельное архитектурное решение.
- `Docs` - основной пользовательский вход в методологию.
- `Examples` - отдельное пространство для полноценных примеров, а не часть onboarding.
- `Tools` - раздел про существующие и планируемые инструменты FEOD.
- `Blog` - раздел для статей и размышлений, который не заменяет reference и guides.
- `Community` - раздел для коммуникации, участия и внешних ресурсов сообщества.

## Раздел, который исключён

Раздел `Прочее` в IA не используется.

Материалы из категории `Прочее` распределяются по нормальным разделам:

- вопросы и короткие ответы -> `FAQ`;
- определения терминов -> `Glossary`;
- планы развития -> `Roadmap`;
- вводный и позиционирующий контент -> `About`.

Нельзя создавать новый контейнер для разнородных материалов под именем `Прочее`, `Misc`, `Разное` или аналогичным.

## Принцип разделения контента

В документации FEOD должны быть явно разведены следующие типы контента:

- `onboarding` - первый вход в методологию;
- `tutorial` - пошаговое обучение на связном сценарии;
- `guides` - практические рекомендации по отдельным задачам;
- `reference` - строгие правила, контракты и определения;
- `tools` - описание инструментов и сценариев их применения;
- `about` - мотивация, сравнения и позиционирование.

Правила:

- advanced-темы не попадают в первый обучающий путь;
- onboarding не смешивается с reference;
- tutorial не превращается в каталог несвязанных советов;
- guides не подменяют собой glossary и reference;
- about не должен мешать быстрому старту.

## Нормы по разделам

### Get Started

Назначение раздела:

- дать читателю быстрый вход в FEOD;
- объяснить, что это такое и зачем это нужно;
- провести по базовому пути без углубления в продвинутые темы.

Ограничения:

- advanced-темы сюда не выносятся;
- reference-детализация не должна перегружать первые страницы.

### Tutorial

Назначение раздела:

- обучать через последовательные сценарии;
- показывать связный путь от задачи к структуре проекта.

Ограничения:

- tutorial не дублирует reference;
- tutorial не должен быть местом для разрозненных правил.

### Core Concepts

Назначение раздела:

- зафиксировать базовые идеи методологии;
- объяснить основные термины и принципы, которые нужны до практических решений.

### Structure

Назначение раздела:

- описать каждый верхний уровень FEOD как отдельный reference-объект;
- дать читателю стабильный набор страниц по `app`, `pages`, `modules`, `common`, `global`.

### Guides

Назначение раздела:

- отвечать на практические вопросы автора проекта;
- давать решение типовых задач и антипримеров.

### Reference

Назначение раздела:

- быть строгим источником правил и определений;
- хранить термины, контракты, naming rules, import matrix и glossary.

Ограничения:

- в reference не должно быть двусмысленных или разговорных формулировок;
- спорные термины должны использоваться только в одном зафиксированном смысле.

### Tools

Назначение раздела:

- описывать инструменты FEOD и их реальные сценарии;
- не обещать функциональность, которая ещё не оформлена как roadmap или существующий инструмент.

### About

Назначение раздела:

- хранить мотивацию, сравнения и развитие методологии;
- выносить сюда большие объясняющие и позиционирующие материалы, которые мешали бы первому обучающему пути.

## Правила первого обучающего пути

Первый обучающий путь состоит из:

- `Обзор`;
- `Быстрый старт`;
- `FEOD за 5 минут`;
- базовых материалов `Tutorial`;
- ключевых страниц `Core Concepts`.

Ограничения для этого пути:

- advanced-темы не появляются раньше базовых правил модулей, уровней, `public API` и импортов;
- сравнения, философские отступления и roadmap не должны прерывать первый обучающий сценарий;
- материалы из `About`, `Blog` и глубокого `Reference` не подменяют стартовый маршрут.

## Правила для авторов

Перед публикацией новой страницы автор проверяет:

1. Страница помещена в один тип контента: onboarding, tutorial, guides, reference, tools или about.
2. Страница не создаёт новый раздел вместо уже утверждённого.
3. Материалы `Прочее` не появляются повторно под новым названием.
4. Продвинутые темы не просачиваются в первый обучающий путь.
5. Если страница относится к `Docs`, она укладывается в утверждённый sidebar или сопровождается отдельным решением об изменении IA.
